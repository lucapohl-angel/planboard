# UI and UX planning

Use for app workflows, controls, forms and navigation. Research checked 2026-10-25.

Start with the user task, prior context and expected outcome. Identify entry, normal completion, cancellation, empty/loading/error states and recovery. Map the smallest useful flow. A sitemap describes destinations; a state flow connects screens to actions and is more useful when a few screens change dynamically. [NN/g wireflows](https://www.nngroup.com/articles/wireflows/).

Review feedback/status, familiar terminology, consistent controls, undo/back paths, prevention of costly errors, recognizable choices and understandable recovery. These are heuristic review questions, not proof that a design passed user testing. Plan keyboard order and focus restoration alongside visual states. [NN/g usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/).

Apply proximity/common region to meaningful groups; similarity to equivalent roles; Fitts to target size and travel; Hick to decision complexity; Jakob to familiar interaction behavior. Reduce irrelevant choices, not useful capabilities. Do not turn Miller’s memory observation into an arbitrary maximum menu length or treat any law as a universal numerical gate. [Laws of UX](https://lawsofux.com/).

Deliver a task flow, critical state descriptions and realistic usability checks. For each issue, name the affected task and consequence before proposing a change. Reuse the project's existing controls and design tokens; consult Design Continuity for implementation. Only claim usability improvements measured in an actual test as findings; otherwise label them hypotheses.
